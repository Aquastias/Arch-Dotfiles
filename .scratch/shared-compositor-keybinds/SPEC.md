# Spec: shared keybind vocabulary across niri and Hyprland

Status: done (commit 5bc7669) — tickets 01-03 implemented. Open manual checks:
`niri validate` on a niri box, and confirm hyprland.conf loads on next login.

Related: ADR 0096 (this feature — shared keybinds + skel-seeded Hyprland
config). Builds on ADR 0095 (curated niri config served via /etc/skel — the
delivery pattern this mirrors for Hyprland), ADR 0090 (niri adapter + Noctalia
preset), ADR 0021/0062 (core-only adapters — the stance this amends for the
config layer only), ADR 0093/0094 (Noctalia preset packages + config).

## Problem Statement

The operator runs two Wayland compositors — niri and Hyprland — and switches
between them. Today switching does not "feel like home": the same physical key
does different things in each. niri's shipped config is near-empty (`Mod+Return`
+ `Print` only), so most of the compositor is unbound; the Hyprland config is
the stock autogenerated `hyprland.conf`, uncommitted and living outside the
dotfiles repo. Worse, the two stock sets actively conflict — `Super+Q` is
*terminal* in Hyprland but *close window* in niri — so muscle memory built in
one compositor actively misfires in the other.

## Solution

Design one deliberate keybind vocabulary and apply it to both compositors so the
shared keys mean the same thing everywhere. Where the two stock sets clashed,
the niri/community convention wins (Hyprland's awkward stock letters lose). The
same key drives the compositor-native tool behind it (the launcher/lock keys
spawn Noctalia on niri, `wofi`/`hyprlock` on Hyprland). niri keeps its
scrollable-tiling-only actions (overview, columns, consume/expel, monitor nav)
on keys Hyprland leaves free, so they never cost cross-compositor muscle memory.

The Hyprland config is brought into the dotfiles repo as a single stow-able
source and — like the niri config (ADR 0095) — seeded into `/etc/skel` by the
Hyprland adapter, so a fresh box boots the shared keybinds. Apps stay
operator-supplied (core-only, ADR 0021/0062): the `wofi`/`dolphin`/`playerctl`
binds are present but no-op until the operator installs their pick — with the
sole exception of `hyprlock`, added to Hyprland core so the lock bind is never a
dead no-op. On niri, `playerctl` joins the Noctalia preset so the media keys
work out-of-box on that already-prepared desktop.

## User Stories

1. As an operator who uses both niri and Hyprland, I want `Super+Return` to open
   my terminal in both, so that launching a terminal is reflexive regardless of
   compositor.
2. As an operator, I want `Super+Q` to close the focused window in both
   compositors, so that the `Q`-means-terminal-vs-close conflict never bites me.
3. As an operator, I want `Super+D` to open the app launcher in both, so that
   finding an app is the same gesture everywhere (Noctalia on niri, wofi on
   Hyprland).
4. As an operator, I want `Super+Shift+E` (and `Ctrl+Alt+Delete`) to quit the
   session in both, so that logging out is consistent.
5. As an operator, I want `Super+F` to toggle fullscreen in both, so that
   maximising a window is reflexive — including on Hyprland, which shipped no
   fullscreen bind at all.
6. As an operator, I want `Super+V` to toggle floating in both, so that pulling
   a window out of tiling is the same gesture.
7. As an operator, I want `Super`+arrows and `Super`+HJKL to move focus in both,
   so that navigation feels identical (accepting niri splits H/L = column,
   J/K = window-in-column).
8. As an operator, I want `Super+Ctrl`+arrows/HJKL to move the focused window in
   both, so that rearranging windows is the same gesture.
9. As an operator, I want `Super+1`–`9` to switch workspaces in both, so that
   jumping to a workspace is identical.
10. As an operator, I want `Super+Shift+1`–`9` to send the focused window to a
    workspace in both, so that my long-standing Hyprland move-to-workspace habit
    keeps working on niri (even though niri's own default uses `Ctrl`).
11. As an operator, I want `Super+Alt+L` to lock the screen in both, so that
    locking is reflexive (Noctalia lockscreen on niri, hyprlock on Hyprland).
12. As an operator, I want the media, volume, and brightness keys to work
    identically in both, so that hardware keys behave the same everywhere.
13. As an operator on niri, I want the media keys to work the moment I log in,
    so that I don't have to hand-install a controller on the prepared desktop.
14. As an operator, I want `Super`+drag to move a window and `Super`+right-drag
    to resize in both, so that mouse manipulation is consistent.
15. As an operator, I want `Print` to take a screenshot on niri via its built-in
    capture, so that screenshots need no extra tooling on the prepared desktop.
16. As an operator on niri, I want `Super+O` to open the overview, so that I can
    use niri's zoomed-out workspace view.
17. As an operator on niri, I want `Super+R` / `Super+Shift+R` to cycle preset
    column widths, so that I can resize columns to sensible presets fast.
18. As an operator on niri, I want `Super+[` / `Super+]` to consume/expel a
    window into or out of a column, so that I can build and break columns.
19. As an operator on niri, I want `Super+W` to toggle tabbed column display, so
    that I can stack windows as tabs.
20. As an operator on niri, I want `Super+C` to center the focused column and
    `Super+-` / `Super+=` for finer width adjustment, so that I can fine-tune the
    scrollable layout.
21. As an operator on niri, I want `Super+M` to maximise a window to the screen
    edges, so that I have an edge-to-edge maximise distinct from fullscreen.
22. As an operator on niri, I want `Super+Shift`+HJKL/arrows to focus a monitor
    and the matching `Ctrl` variants to move a column between monitors, so that
    multi-monitor nav is available without colliding with move-to-workspace.
23. As an operator on niri, I want `Super+Page_Up/Down` and `Super+U/I` to move
    between workspaces directionally, so that I can use niri's dynamic vertical
    workspace stack.
24. As an operator on niri, I want `Super+Shift+P` to power off the monitors, so
    that I can blank displays on demand.
25. As an operator on Hyprland, I want `Super+E` to open my file manager and
    `Super+S`/`Super+Shift+S` for the scratchpad, so that I keep those Hyprland
    conveniences that niri has no equivalent for.
26. As an operator, I want the niri "Important Hotkeys" overlay to stay off at
    login but remain reachable via `Mod+Shift+/`, so that the now-populated
    cheatsheet is available on demand without a welcome-screen nag.
27. As an operator, I want my Hyprland config version-controlled in the dotfiles
    repo, so that it is no longer an uncommitted stock file I could lose.
28. As an operator installing a fresh Hyprland box, I want the curated keybinds
    seeded by default, so that the shared layout is present without me copying a
    config in.
29. As an operator, I want the lock key to always lock on a fresh Hyprland box,
    so that I am never left with a dead lock bind (hyprlock ships in core).
30. As a maintainer, I want the Hyprland adapter to stay core-only for apps, so
    that seeding a config does not turn into the installer picking my launcher,
    file manager, or screenshot tool.
31. As a maintainer, I want a single authored source per config file, so that the
    stowed copy and the skel-seeded copy can never drift.

## Implementation Decisions

- **Two authored config files, one shared layout.** `.config/niri/config.kdl`
  (KDL, existing) and a new `.config/hypr/hyprland.conf` (Hyprland syntax) each
  carry the vocabulary in their own dialect. There is no shared source across
  the two dialects; the keybind contract is maintained in both by hand (called
  out in ADR 0096's consequences).
- **Canonical shared binds** (both compositors): `Super+Return` terminal
  (kitty), `Super+Q` close, `Super+D` launcher, `Super+Shift+E` +
  `Ctrl+Alt+Delete` quit, `Super+F` fullscreen, `Super+V` float, `Super`+arrows/
  HJKL focus, `Super+Ctrl`+arrows/HJKL move window, `Super+1`–`9` focus
  workspace, `Super+Shift+1`–`9` move-to-workspace, `Super+Alt+L` lock,
  `Super`+drag move / right-drag resize, XF86 volume/brightness/media keys.
- **Per-compositor tools behind identical keys.** Launcher: `noctalia msg
  panel-toggle launcher` on niri, `wofi --show drun` on Hyprland. Lock:
  Noctalia lockscreen on niri, `hyprlock` on Hyprland. niri keeps its native
  `Super+Ctrl`+`<n>` move-to-workspace in addition to the shared
  `Super+Shift`+`<n>`.
- **niri-only additions** on keys Hyprland leaves free: `Super+O` overview,
  `Super+R`/`Shift+R` width presets, `Super+[`/`]` consume-expel, `Super+W`
  tabbed, `Super+C` center-column, `Super+-`/`=` fine width, `Super+M`
  maximize-to-edges, `Super+Shift`+HJKL/arrows focus-monitor (+ `Ctrl` move to
  monitor), `Super+U/I` & `Super+Page_Up/Down` directional workspace nav,
  `Super+Shift+P` power-off-monitors. `Print`/`Ctrl+Print`/`Alt+Print` use
  niri's built-in screenshot.
- **Hyprland-only additions:** `Super+E` file manager (dolphin), `Super+S` /
  `Super+Shift+S` scratchpad. These have no niri equivalent and stay asymmetric.
- **Dropped:** `Super+0` / workspace 10 (niri is dynamic; Hyprland's 10th is
  unused). Hyprland's stock `Print` stays unbound (no screenshot tool in
  core-only).
- **niri overlay** stays `hotkey-overlay { skip-at-startup }` (unchanged); the
  populated overlay is reachable via `Mod+Shift+/`.
- **Hyprland config delivery mirrors ADR 0095.** `.config/hypr/hyprland.conf` is
  a single stow-able repo source; `lib/chroot.sh` stages it into the Hyprland
  adapter's curated dir (a block parallel to the niri staging that already
  exists in `chroot.sh`); `extras/desktop/hyprland/hyprland.sh` copies it into
  `/etc/skel/.config/hypr/`. The adapter gains `HYPR_SEED_ROOT` and
  `HYPR_CURATED_DIR` injectable seams mirroring niri's `NIRI_SEED_ROOT` /
  `NIRI_CURATED_DIR`.
- **Package-map changes.** Add `hyprlock` to the Hyprland core install (so the
  lock bind is never a dead no-op). Add `playerctl` to the Noctalia preset in
  `lib/packages/niri.sh` (so niri media keys work out-of-box). Both are one-line
  additions to the existing pure package maps shared with the Package Resolver.
- **Core-only for apps preserved (Q15-a).** The Hyprland adapter installs no
  launcher, file manager, screenshot tool, or `playerctl`; those binds no-op
  until the operator installs their pick. `hyprlock` is the sole exception,
  justified as a safety essential.

## Testing Decisions

- **What a good test asserts here:** externally observable adapter behavior —
  which packages get installed, which files land in `/etc/skel`, and that a
  seeded file is a verbatim copy of the single repo source — never the internal
  shape of the shell functions. Prior art is the existing niri/Hyprland adapter
  bats suites, which stub `pacman`/`systemctl` and inject `ROOT` / `*_SEED_ROOT`
  / `*_CURATED_DIR` temp dirs.
- **`hyprland-adapter.bats` (primary seam).** Following the niri suite's skel
  tests (`niri-adapter.bats` "noctalia seeds the curated config … to /etc/skel
  (ADR 0095)" and "warns but does not abort when the curated dir is absent"),
  add: the curated `hyprland.conf` is seeded to `/etc/skel/.config/hypr/` and
  equals the injected `HYPR_CURATED_DIR` source; `hyprlock` appears in the
  installed core; the adapter still installs no other companion apps
  (existing "installs no companion packages" assertion holds); and the adapter
  warns-but-does-not-abort when the curated dir is absent.
- **`niri-adapter.bats` (existing seam, reused).** Extend the preset-package
  assertion so `playerctl` is expected in the Noctalia preset install (alongside
  the existing niri "installs the Noctalia work preset" test).
- **Not covered by bats:** the correctness of the bind lines themselves. niri
  config is validated with `niri validate`; the Hyprland config is validated by
  the running compositor. A VM boot-test asserting live bind behavior is out of
  scope.

## Out of Scope

- Turning Hyprland into a batteries-included preset (installing `wofi`,
  screenshot tooling, a file manager, `playerctl`). Rejected as Q15-b in the
  design; only `hyprlock` is added.
- A file manager or scratchpad equivalent on niri — niri has neither concept and
  the niri box ships no file manager.
- Seeding a `hyprlock.conf`; hyprlock runs on its built-in defaults.
- Any change to the niri "Important Hotkeys" overlay startup behavior (stays
  skipped).
- A VM boot-test / runtime keybind-behavior harness.
- Theming, animations, window rules, or any non-keybind section of either
  config.

## Further Notes

- niri's H/L = column and J/K = window-in-column split is inherent to its
  scrollable model; it is the closest possible mapping to Hyprland's directional
  focus, not an exact one, and is accepted as such.
- niri's move-to-workspace always follows the window (no silent-move
  equivalent); the shared `Super+Shift`+`<n>` bind accepts this behavioral
  difference from Hyprland's `movetoworkspacesilent`.
- The `install-niri.jsonc` bools / `packages/niri.sh` / curated `config.toml`
  drift-guard relationship (ADR 0093/0094) is unchanged; the `playerctl`
  addition is to the non-negotiable preset base, not a toggle.
