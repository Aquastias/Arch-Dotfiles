# ADR 0159: Umbriel adapter, `desktop[0]` is the Default Session

## Status
Accepted — design only; not yet implemented.

## Context
Umbriel is the Noctalia project's own wlroots compositor (scrolling, dwindle,
master layouts; TOML config at `~/.config/umbriel/config.toml`, live reload,
`umbriel config validate`). Noctalia is its first-class shell. It is young:
upstream says config keys and binds may change between releases.

Arch Wiki grounding: there is no Umbriel page. Its facts come from upstream
docs (docs.noctalia.dev/umbriel, repo `docs/user/`, `PACKAGING.md`), as
noctalia-greeter's did ([ADR 0158]).

Packaging: only `umbriel-git` and `xdg-desktop-portal-umbriel-git` are real
AUR packages; `umbriel` / `xdg-desktop-portal-umbriel` are 0.0.0
placeholders. Its `wlroots0.20` dependency is in `extra`.

No "default desktop" exists today: a multi-desktop host (`kde`, `niri`,
`hyprland`) gets whatever its DM picks first or last.

## Decision
- **Umbriel adapter** (`extras/desktop/umbriel/`), a fourth Desktop
  Environment Adapter, core-only like niri. Packages from AUR via the vetted
  paru pass ([ADR 0143]/[0149]); switch to the non-git names once upstream
  tags a release.
- The adapter enables `seatd` + the `seat` group itself, like Hyprland
  ([ADR 0068]): same libseat DRM-master path, and an umbriel-only host must
  not depend on Hyprland being present.
- Joins the shared Wayland Shell Companion ([ADR 0097]); its compositor
  plugin slice is empty (Noctalia supports Umbriel natively).
- Curated `.config/umbriel/` (`config.toml` + `conf.d/`), stowable and
  seeded via `/etc/skel` ([ADR 0094]/[0095]/[0107]). Binds follow the shared
  niri/Hyprland map ([ADR 0096], Meta+X close [ADR 0113]), not upstream
  defaults; Umbriel-only features (overview, tab groups, scratchpad) take
  keys the map leaves free.
- `umbriel-pure` stock profile ([ADR 0112]): bare compositor, seeds nothing
  (Umbriel falls back to its packaged config).
- **Default Session = `environment.desktop[0]`**, the element-0 convention
  `locale`/`keymap`/kernel already use. Every Display Manager Adapter seeds
  it as the *remembered last* session, never a forced default: a first-boot
  preselect the operator's next pick overrides ([ADR 0091] spirit).
- `desktop` and `laptop` become `["umbriel", "kde", "niri", "hyprland"]`.
- Feature Audit ([ADR 0152]) gains an Umbriel probe, `audit-binds.jsonc`
  for every shipped bind, Umbriel in `arch-audit`, and an `umbriel-pure`
  variant.

## Considered Options
- **Replace niri/Hyprland with Umbriel on desktop/laptop** — rejected: the
  young upstream needs fallbacks; additive is reversible.
- **Wait for a tagged release** — rejected: no ETA; `-git` is vetted.
- **Forced greeter default (`[session].default`)** — rejected: overrides the
  operator's choice every login.
- **A separate `default_session` profile key** — rejected: a second source
  of truth beside the desktop order.

## Consequences
- Reordering `environment.desktop` changes the first-boot session; the
  Guided desktop row marks the first entry as default.
- `-git` builds track upstream HEAD: an upstream config-key change can break
  the curated config; the audit's `umbriel config validate` probe catches it.
