# ADR 0161: Hybrid laptop completion (Legion 5 15ARH7H)

## Status
Accepted — not yet implemented. Amends [ADR 0053].

## Context
The laptop (`chronos`) is a Lenovo Legion 5 15ARH7H: Ryzen 5 6600H (Radeon
660M iGPU), RTX 3060 6 GB (Ampere), 16 GB RAM. [ADR 0053] hardened the
AMD+NVIDIA hybrid (Early KMS, RTD3, VRAM preserve, suspend services), but the
box is still short of a finished gaming laptop:

- **No `prime-run`.** [ADR 0053]'s acceptance checklist and the Hyprland
  aquamarine pin both assume PRIME offload via `prime-run`, yet nothing
  installs `nvidia-prime`.
- **No Dynamic Boost.** `nvidia-powerd` ships in `nvidia-utils` but is never
  enabled; the Arch Wiki (NVIDIA) says it needs firmware support, and some
  Legions need Performance mode (BIOS or Fn+Q).
- **No 32-bit AMD Vulkan.** The nvidia map's explicit `lib32-nvidia-utils`
  satisfies Steam's `lib32-vulkan-driver`, so `lib32-vulkan-radeon` is never
  pulled; 32-bit Vulkan only sees the dGPU. The AMD desktop gets it only by
  provider luck.
- **No Legion tooling.** The Arch Wiki (Laptop/Lenovo) routes Legion fan
  control, CPU temperature and Fn+Q modes through LenovoLegionLinux; upstream
  confirms the 15ARH7H (BIOS JUCN55WW) for sensors, fan curve and power
  profile. AUR ships only `lenovolegionlinux-dkms-git` (module) and
  `lenovolegionlinux-git` (CLI/GUI + `legiond`).
- **Uncapped ZFS ARC.** With 16 GB shared by ARC and games, memory pressure
  falls on the games.

## Decision
- **Hybrid-gated additions** live in the existing GPU Hardening gate
  (`lib/chroot/gpu.sh`, amd+nvidia), reported by the Package Resolver so
  query and install cannot drift:
  - install `nvidia-prime` (`prime-run`);
  - enable `nvidia-powerd.service`.
  Single-vendor NVIDIA hosts get neither: no offload, no laptop boost.
- **`lib32-vulkan-radeon`** joins the AMD driver map for every AMD host;
  the existing multilib filter drops it when multilib is off.
- **LenovoLegionLinux** is two laptop-only `packages.aur` entries
  (`lenovolegionlinux-dkms-git`, `lenovolegionlinux-git`) in the laptop
  profile, through the Primary User's vetted paru pass ([ADR 0041],
  [ADR 0149]). A Host Program runs as root via pacman, so it cannot reach the
  AUR; and the install is package-only — the module autoloads through its
  ACPI/WMI device ids. It installs the DKMS module and the tools;
  **`legiond` stays disabled** — power-profiles-daemon remains the sole
  owner of `platform_profile` ([ADR 0080]).
- **`options.zfs.arc_max`** — a profile-only option (no Guided row), default
  unset (ZFS default). The laptop sets `4G`; it is written as
  `zfs_arc_max` to `/etc/modprobe.d/zfs.conf`. The desktop stays uncapped.
- **Hybrid BIOS mode only.** The panel must stay on the iGPU; discrete (MUX)
  mode is unsupported and undetected. It would black-screen Hyprland's
  `AQ_DRM_DEVICES=aq-igpu` pin and needs a different backlight driver.
- niri and Umbriel get **no iGPU pin** for now; the on-laptop checklist
  verifies they drive the iGPU, and a pin is added only if one does not.

## Considered Options
- **`nvidia-prime` / `nvidia-powerd` on every NVIDIA host** — rejected:
  offload and Dynamic Boost are hybrid-laptop features.
- **Skip LenovoLegionLinux, rely on in-kernel `ideapad_laptop`** — rejected:
  no fan curves or CPU temperature. Accepted cost: an out-of-tree `-git`
  DKMS module can break on an LTS kernel bump.
- **Enable `legiond`** — rejected: two daemons writing `platform_profile`.
- **Detect discrete mode** — rejected: one machine, operator-controlled BIOS;
  a documented constraint is cheaper than detection.
- **Keyboard RGB and Wi-Fi power-save tuning** — out of scope: no confirmed
  tool for the 15ARH7H 4-zone keyboard, and the Wi-Fi chip is unconfirmed.

## Consequences
- Not VM-verifiable (no hybrid GPU in QEMU): pure-core bats plus the
  on-Legion checklist, extended with `prime-run glxinfo` on the NVIDIA
  renderer, `nvidia-smi -q` showing the Dynamic Boost limit, LLL sensors and
  fan curve, `arc_max` applied, brightness keys, battery conservation via
  Noctalia's plugin, and niri/Umbriel on the iGPU.
- Flipping the BIOS to discrete mode is an operator-side break, not a bug.
- [ADR 0114]'s "one software image" holds for software, not hardware: the
  Fleet Golden desktop/laptop parity check exempts the laptop-only hardware
  packages (LenovoLegionLinux).
