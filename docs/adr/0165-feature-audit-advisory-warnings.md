# ADR 0165: Feature Audit tiers warnings as Advisories

## Status
Accepted — implemented. Amends [ADR 0152].

## Context
[ADR 0152] made every error-shaped line a Finding: any of err, error,
warn, warning, failed, failure, fatal, critical in a log, and every journal
line at priority warning or above. Harmless upstream chatter (Qt, GLib, KWin,
portal warnings) therefore failed the run, and Known Noise grew to 90+
entries, most of them silencing warnings rather than explaining errors. A
desktop Audit Run could not pass without an approval round per upstream
release.

## Decision
- **Two tiers.** A [[Finding]] (blocking) is a probe FAIL, a coredump, a
  failed unit, a journal line at priority err or above (0–3), or a log line
  carrying a non-warning error-word. An [[Advisory]] is a journal line at
  priority warning (4), or a log line whose only error-word is warn/warning.
  A line with both (e.g. `[WARN] unit failed`) stays a Finding.
- The guest collector splits each journal capture by priority: `*.lines`
  (`-p err`) and `*.warnings` (`-p warning..warning`), same source name.
- The report writes Findings to `findings.jsonl` (the exit code), Advisories
  to `advisories.jsonl`, and lists Advisories in their own `findings.md`
  section with frequency. The run passes with zero Findings.
- Known Noise applies to both tiers. Entries whose lines are all
  warning-level are pruned against a fresh desktop run's split captures.

## Considered Options
- **Demote warnings only in non-journal logs** — rejected: most noise is
  journal warnings.
- **Collect the journal at `-p err` only** — rejected: a regression that only
  warns would vanish; Advisories keep it visible.
- **Advisories in a separate file only** — rejected: one report to read.

## Consequences
- A new upstream warning no longer blocks; a new error still does.
- Pruning is limited to entries a split capture proves warning-only;
  entries for variants not re-run stay until those variants run again.
