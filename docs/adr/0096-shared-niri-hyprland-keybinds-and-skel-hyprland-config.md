# niri and Hyprland share one keybind vocabulary; Hyprland gains a
# skel-seeded config

---
Status: accepted. Amends the "operator brings all dotfiles" stance of ADR
0021/0062 for the *config* layer only (apps stay operator-supplied). Extends
ADR 0095's skel-seed delivery from niri to Hyprland.
---

The niri config (`.config/niri/config.kdl`) shipped near-empty — `Mod+Return`
and `Print` only — while the Hyprland config was the stock autogenerated
`hyprland.conf`, uncommitted and living outside the repo. The operator switches
between the two compositors and wants the switch to "feel like home": the same
keys doing the same things. But the two stock sets actively clash (`Q` is
*terminal* in Hyprland, *close* in niri) and the two compositors have different
spatial models (Hyprland dwindle vs niri scrollable columns), so parity is a
design, not a copy.

## Decision

**One canonical keybind vocabulary across both compositors**, with
niri/community convention as the tie-breaker where the stock choices clashed —
Hyprland's awkward defaults lose. Canonical shared binds: `Super+Return`
terminal, `Super+Q` close, `Super+D` launcher, `Super+Shift+E` quit, `Super+F`
fullscreen, `Super+Shift+<n>` move-window-to-workspace. Identical keys drive
**per-compositor tools**: the launcher and lock keys spawn Noctalia on niri and
`wofi`/`hyprlock` on Hyprland. niri keeps its scrollable-only actions (overview,
consume/expel, column widths, tabbed columns, monitor nav) on keys Hyprland
leaves free, so they never cost cross-compositor muscle memory.

**Hyprland now ships a curated `hyprland.conf` served via `/etc/skel`**, single-
source-and-stowable, mirroring ADR 0095's niri machinery (`chroot.sh` stages the
repo file; `extras/desktop/hyprland/hyprland.sh` copies it into skel). This
amends ADR 0021/0062's "operator brings all dotfiles" — but for the *config*
layer only. **Apps stay operator-supplied** (Q15-a): the `wofi`/`dolphin`/
`playerctl`/screenshot binds are present but no-op until the operator installs
their pick. The sole exception is **`hyprlock`, added to Hyprland core**, so the
`Super+Alt+L` lock bind is never a dead no-op — a lock key that silently does
nothing is a safety hole. On the niri side `playerctl` is added to the Noctalia
preset so the media keys work out-of-box on that already-prepared desktop.

## Considered Options

- **niri-only mirror of Hyprland's stock binds.** Rejected: it canonises the
  awkward stock letters (`Q` terminal, `C` close, `R` launcher, `M` exit) and
  leaves the Hyprland config uncommitted and un-curated.
- **Keep Hyprland's stock letters canonical, retrain niri.** Rejected for the
  same reason — the stock set is the worse of the two.
- **Batteries-included Hyprland preset** (adapter installs `wofi`, screenshot
  tool, etc.). Rejected: reverses core-only wholesale; the keybind *layout* is
  what delivers "feel like home," not the adapter picking the operator's apps.

## Consequences

- Two config files now share one layout; editing the keybind contract means
  editing both (niri KDL + Hyprland conf) — there is no shared source.
- Scratchpad (`Super+S`) and file manager (`Super+E`) stay **Hyprland-only** —
  niri has no scratchpad and the niri box ships no file manager. Workspace `10`
  (`Super+0`) is dropped; niri is dynamic and Hyprland's 10th is unused.
- The niri "Important Hotkeys" overlay stays `skip-at-startup` (ADR-less, commit
  `ce14c9e`); the now-populated overlay is still reachable via `Mod+Shift+/`.
- A fresh Hyprland box boots the curated keybinds but `Super+D`/`Super+E` no-op
  until the operator installs a launcher / file manager; `Super+Alt+L` works
  (hyprlock is in core).
