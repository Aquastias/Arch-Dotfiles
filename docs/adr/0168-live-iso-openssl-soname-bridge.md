# ADR 0168: Bridge a live-ISO soname bump with Arch's compat package

## Status
Accepted — implemented.

## Context
The live ISO is an archived Arch snapshot ([ADR 0023]); the archzfs repo
builds against current Arch. On 2026-11-10 core moved OpenSSL 3 → 4.1.0
and archzfs rebuilt zfs-utils 2.4.4-3 against it the next day. The
bootstrap's `pacman -Sy` then `pacman -S zfs-utils` is exactly the partial
upgrade the Arch Wiki forbids (System maintenance § Partial upgrades are
unsupported): zfs-utils arrived without the OpenSSL it links against, and
pool creation died with `zpool: error while loading shared libraries:
libcrypto.so.4`.

The Wiki's remedy is a full `pacman -Syu`. On the live ISO that replaces
the running kernel's modules (the DKMS build and `modprobe zfs` need them)
and does not fit the RAM-backed cowspace.

## Decision
After installing the archzfs packages, check `zpool` with `ldd`. Only when
a library is missing, install `openssl` (current) together with
`openssl-3`, Arch's own package carrying the old `libcrypto.so.3` /
`libssl.so.3` soname, in one transaction: zfs-utils gets OpenSSL 4 and the
ISO's other binaries (pacman, curl) keep OpenSSL 3. Fail loudly when a
library is still missing.

## Considered Options
- **Full `pacman -Syu` on the live ISO** — rejected: breaks the running
  kernel's modules and overflows cowspace.
- **Pin an older zfs-utils** — rejected: archzfs keeps only the newest build
  in its release.
- **Symlink libcrypto.so.4 → .so.3** — rejected: the Wiki forbids it; a
  soname bump means the ABI changed.

## Consequences
- The bridge is specific to OpenSSL; another soname bump between the ISO
  and archzfs fails with the same clear error and needs its own compat
  package added here.
- The installed system is unaffected: pacstrap installs a consistent,
  current package set.
