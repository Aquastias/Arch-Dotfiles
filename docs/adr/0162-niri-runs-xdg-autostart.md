# ADR 0162: niri runs XDG autostart; wlroots sessions completion

## Status
Accepted — not yet implemented. Amends [ADR 0131] (its niri premise) and
[ADR 0080] (blueman).

## Context
[ADR 0131] assumed niri, like Hyprland and Umbriel, never processes
`/etc/xdg/autostart`. Wrong for niri: the packaged `niri.service` has
`Wants=xdg-desktop-autostart.target`, so systemd's XDG autostart generator
starts every entry whose `OnlyShowIn`/`NotShowIn` admits `niri`. On a KDE
co-install the desktop Audit Run showed kalendarac (and the akonadi it
pulls), kdeconnectd and nm-applet (`NotShowIn=KDE;GNOME;`) starting inside
niri — duplicating Noctalia and logging portal errors. Hyprland
(`start-hyprland`) and Umbriel are unaffected.

Three more gaps across the wlroots sessions:
- Dolphin owns D-Bus activation of `org.freedesktop.FileManager1`, so
  "Show in folder" from browsers/Electron opens Dolphin while `Super+E`
  opens pcmanfm-qt ([ADR 0100]). pcmanfm-qt ≥ 1.1.0 implements
  FileManager1 but ships no activation file; it answers only in daemon mode
  (`pcmanfm-qt -d`; upstream issues #1834/#2127).
- niri's packaged portals config routes `Secret` to `gnome-keyring`, which
  is not installed; the fleet's Secret Service is kwallet (it Provides
  `org.freedesktop.secrets`, unlocked by SDDM's `pam_kwallet5`).
- Hyprland alone ships blueman ([ADR 0080]), which predates Noctalia's
  Bluetooth panel ([ADR 0097]). It also overwrites a package-owned
  `/etc/xdg/autostart` file, which the next upgrade reverts.

## Decision
- **Suppress, per app, by systemd drop-in**: on a KDE co-install, the niri
  adapter writes
  `/etc/systemd/user/app-<id>@autostart.service.d/` with
  `ConditionEnvironment=!XDG_CURRENT_DESKTOP=niri`. A **blocklist**:
  kalendarac, the kdeconnect daemon, nm-applet, the Discover notifier
  (final ids from the VM's `/etc/xdg/autostart`). Kept: `pam_kwallet_init`
  (wallet unlock), at-spi, `xdg-user-dirs`. [ADR 0131]'s seeded script
  stays — it still owns `~/Projects`.
- **pcmanfm-qt daemon**: every compositor's curated autostart (niri,
  Hyprland, Umbriel) starts `pcmanfm-qt -d`, so the running instance owns
  FileManager1 before Dolphin can be activated. Plasma is untouched.
- **niri Secret portal → kwallet** on a KDE co-install, via an
  `/etc/xdg-desktop-portal/niri-portals.conf` override; a box without KDE
  keeps the packaged file.
- **Drop blueman** from the Hyprland adapter; Noctalia's Bluetooth panel is
  the one tray on all three compositors.

## Considered Options
- **Overwrite `/etc/xdg/autostart` entries with `NotShowIn=niri`** —
  rejected: package-owned, reverted on upgrade (the blueman bug).
- **Mask the generated units** — rejected: Plasma starts the same
  `app-*@autostart` units, so it would kill them in KDE too.
- **Mask `xdg-desktop-autostart.target`** — rejected: Plasma's systemd
  startup uses it.
- **Allowlist instead of blocklist** — rejected: silently drops future
  wanted entries (e.g. a new wallet or a11y helper).
- **A FileManager1 D-Bus service file for pcmanfm-qt** — rejected: upstream
  #2127 reports the first `ShowItems` opens home, not the target.
- **Add blueman to niri/Umbriel** — rejected: a second Bluetooth UI.

## Consequences
- One resident pcmanfm-qt per wlroots session.
- A new KDE app that autostarts in niri is a blocklist edit, caught by the
  niri session journal in the Feature Audit.
